一份好的笔记，不必从完整的体系开始。它可以从一个具体问题、一段可运行的代码，或一次排查过程开始。

> 本文是站点示例文章，用来演示 Markdown 排版与系列阅读。你可以将它替换为自己的技术文章。

## 为什么保留原稿

公开平台上的排版可以变化，但原稿应该容易保存、迁移和修改。把内容写成 Markdown，可以将正文和展示样式分开管理。

- 正文记录问题与结论。
- 图片保存关键现象和架构。
- 修改记录保留认识变化的过程。

## 用一个问题组织文章

动笔前，先写下这三个问题：

1. 我遇到了什么现象？
2. 我做了哪些尝试，证据是什么？
3. 其他人在什么条件下可以复现？

标题不必覆盖整个领域。与其写一篇泛泛的介绍，不如先把一个小问题解释清楚。

### 把环境写清楚

下面是结构示例，变量名和版本应替换成真实环境：

```json
{
  "topic": "learning-journal",
  "format": "markdown",
  "status": "draft"
}
```

代码块应标记语言，读者才能获得清晰的语法高亮。关键代码之外，最好附上输入、预期输出以及验证方式。

## 建立可重复的目录

```text
posts/
└── my-first-note/
    ├── index.md
    └── images/
```

把一篇文章和它需要的图片放在一起，复制目录就能带走完整内容。对于需要多篇解释的主题，下一步是建立系列，而不是把所有正文堆进一个超长文件。

## 留下下一步

每次学习不一定都得到完整答案。把已经验证的结论和仍然存在的问题分开记录，后续修订时会更容易继续。

**可执行的小练习：** 找一篇旧笔记，补上背景、操作、结果三个部分，再用一句话写出它解决的问题。
